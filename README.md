## Глоссарий

- **Персонаж** — словарь: имя, класс, `hp`, `mana`, `effects` (словарь статусов).
- **Приём** — функция с контрактом
  `move(user, /, *targets, crit=False, **effects)`, где носитель передаётся только позиционно, целей может быть сколько угодно (в том числе ноль — для лечения себя), крит передаётся только по имени, эффекты — именованные аргументы. Сигнатура общая для всех приёмов; какие аргументы приём использует, зависит от его поведения в пункте 2.
- Приём возвращает **кортеж** `(нанесённый урон, применённые статусы)`. Если не хватило маны или зарядов — приём не выполняется и возвращает `None`.
- **Книга приёмов** — словарь имя → функция. Движок игры умеет только одно: вызвать `cast(book, name, user, *targets, log=…, **effects)`.
- **Журнал боя** — список записей `(игрок, приём, урон)`; передаётся в `cast` аргументом.
- У приёма могут быть **заряды** — сколько раз за бой его можно выполнить; каждое выполнение тратит один заряд, у всех таких приёмов их три на бой. Заряды принадлежат персонажу, а не приёму. На каждый бой персонаж получает новый комплект.
- **Договорённости**:
  1. удар по площади без целей — это не ошибка: приём выполняется, урон 0
  2. лечить можно только самого себя — цели игнорируются, крит на лечение не действует
  3. статус поверх такого же статуса заменяет его, они не складываются
  4. сам приём журнал не ведёт, его ведёт `cast`.

## Задание

1. **Реализуйте книгу приёмов и функцию `learn(book, move)`.** Книга это словарь имя → функция, в ней лежат приёмы, которые знает каждый отдельно взятый персонаж. **Книга - своя у каждого из персонажей**. Приём попадает в книгу, только если его сигнатура совпадает с контрактом — по видам параметров, а не по именам. На приём с другой сигнатурой `learn` должен бросать `TypeError`.
2. **Реализуйте пять отдельных приёмов**, соответствующих общему контракту:
   - `strike` — удар по одной цели;
   - `nova` — удар по площади, по всем переданным `*targets`; оберните его в `limited` из пункта 4 с тремя зарядами;
   - `heal` — лечение себя, работает без целей;
   - `status` — накладывает переданные через `**effects` статусы на цели;
   - `critical_strike` — удар по одной цели; с `crit=True` наносит больше урона, чем без крита. Крит принимается только по имени.

   Это имена приёмов в книге. У всех одна сигнатура, но разное поведение. Обычный `strike` не обязан поддерживать крит и накладывать статусы; автотесты проверяют это на `critical_strike` и `status`. `cast` находит приём по имени и вызывает его.

   Если вы уже совместили крит или статусы со `strike`, этот вариант тоже принимается: при отсутствии соответствующего ключа `critical_strike` или `status` автотесты проверяют эту возможность на `strike`. Если отдельный приём есть в книге, проверяется именно он.
3. **Реализуйте фабрику `make_strike(power, element)`**, она должна возвращать приём. Три огненных удара силы 10, 20 и 40 создаются через неё **в цикле** — должны бить по-разному.
4. **Реализуйте приём с зарядами:** обёртка `limited(move, charges)`, которая считает сколько зарядов приема осталось у персонажа через `nonlocal`. Заряды выдаются конкретному персонажу.
5. **Журнал боя** передаётся аргументом. В вашем коде нигде не должно быть `log=[]`, `charges={…}` и подобного в значениях по умолчанию. Проверьте `__defaults__` и `__kwdefaults__` каждого приёма — там не должно быть ничего изменяемого.
6. **`cast` должен раскладывать аргументы по сигнатуре приёма** (`signature(...).bind`), а не вручную. Логический аргумент на месте цели — должен давать `TypeError`, а не проглатывать крит.
7. **Напишите тесты на `pytest`**:
   - три огня бьют на 10, 20 и 40;
   - заряды Сони и Лины независимы;
   - два боя подряд — два разных журнала;
   - `learn` отвергает приём с неправильной сигнатурой;
   - `cast(book, "strike", user, foe, True)` падает с `TypeError`, крит не уезжает в цели;
   - `critical_strike` с `crit=True` бьёт сильнее, чем без крита;
   - приём без маны возвращает `None`, цель не задета;
   - результат `status` — кортеж, статус из `**effects` оказался на цели;
   - **тест, который падает на коде Валеры и проходит на вашем.** Тест, проходящий на обоих, не засчитывается.

## Как сдавать

Пушим в `main`:

- `solution.py` — решение;
- `test_solution.py` — тесты: реализацию берут из фикстуры `impl`, персонажей — из `chars`. Количество тестов не фиксировано; проверить нужно случаи из задания.

Проверить себя до пуша:

```
python3 -m pytest -q                          # на вашем решении — зелёные
python3 -m pytest -q --impl valera_adapter    # на коде Валеры — красные
```

Автопроверка импортирует `solution.py` и вызывает `learn`, `cast`, `make_strike`, `limited` и `book_for(character)` — книгу способностей персонажа и его комплект зарядов. В книге должны быть приёмы `strike`, `nova`, `heal`, `status`, `critical_strike` из пункта 2 и огни `fire10`, `fire20`, `fire40` из пункта 3 — приём из `make_strike` называется `element + power`. Для старых решений без `status` или `critical_strike` действует совместимость, описанная в пункте 2. Огни бьют на 10, 20 и 40; урон остальных приёмов и стоимость в мане — на ваше усмотрение.
